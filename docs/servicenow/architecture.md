# EduPulse Architecture

**Not yet defined.** No platform, scope, portal mechanism, or data model has been chosen for EduPulse. Prior ServiceNow exploration (archived in [`../../archive/2026-10-18-servicenow-exploration/`](../../archive/2026-10-18-servicenow-exploration/)) is exploratory only and is explicitly **not** adopted as architecture, precedent, or baseline — see [`../../CLAUDE.md`](../../CLAUDE.md) §6.

Architecture gets decided through the task process, not written here speculatively:

1. [`../../tasks/backlog/TASK-001-define-edupulse-demo-scope.md`](../../tasks/backlog/TASK-001-define-edupulse-demo-scope.md) must be resolved first — it decides platform (ServiceNow, Zoho Creator, or both), target end users, and the first visible screen/form.
2. Once that's resolved, a feature task is opened for the first real piece of work, and *that* task's `plan.md` is where implementation approach gets decided — grounded in a real baseline/export for whatever platform is chosen, never guessed.
3. This file gets filled in incrementally, after decisions are made and approved, not ahead of them. Each section added here should link back to the task that decided it.

See [`../../tasks/README.md`](../../tasks/README.md) for the task process and [`glossary.md`](glossary.md) for term definitions.
